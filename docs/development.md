# 開発者向けリファレンス

[README](../README.md)にデスクトップ版の起動手順があります。

## 技術構成

- Tauri 2 / Rust: デスクトップアプリの起動、OS操作、データの保存
- React / TypeScript: UI（strictモード）
- Vite: 開発サーバーとフロントエンドビルド
- Tailwind CSS 4 / `@tailwindcss/vite`: スタイルとViteとの統合
- `@types/node`: Vite設定内のNode.js APIを型チェックするために使用

追加した依存関係:

- `@tauri-apps/api`: UIから登録専用のRustコマンドを呼び出すため
- `tauri-plugin-dialog`: OS標準のフォルダ選択をRust側で実行するため
- `serde` / `serde_json`: 型付きデータのJSON変換のため
- `uuid`: 名前やパスに依存しないプロジェクトIDを生成するため
- `tempfile`: 同じ保存先内で一時ファイルを作り、完成したJSONに置き換えるため（テストでも使用）
- `git2`: Git CLIやシェルに依存せず、Rustでリポジトリの状態を読み取るため（SSH・HTTPSなどのデフォルト機能は無効）
- `url`: 起動URLのスキーム・ホスト・認証情報を検証し、正規化して保存するため
- `tauri-plugin-opener`: RustからOSの既定ブラウザに検証済みURLを渡すため（フロントエンドへの汎用起動権限は追加しません）
- `tauri-plugin-global-shortcut`: macOSへのグローバルショートカット登録とキーイベントの受信に使用
- `objc2-app-kit`: クイック再開を閉じたときに、開く前のmacOSアプリへフォーカスを戻すために使用
- `react-markdown` / `remark-gfm`: MarkdownをReactで表示し、表やチェックリストを扱うために使用
- `unified` / `remark-parse`: カードの抜粋用に、Markdownから表示用テキストを取り出すために使用
- Vitest / Testing Library / jsdom: フォーム操作と非同期の成功・失敗を検証するため

UIには汎用のファイル操作やシェル実行の権限を渡していません。

## UIとテーマ

ライト・ダーク・OS追従に対応し、一覧・詳細・設定・各フォームの配色と操作部品を統一しています。
一覧ではプロジェクト名と再開操作を先に置き、次の作業、前回の作業、Git情報を補助情報として表示します。

- `src/styles/theme.css`: 色、フォント、文字サイズ・太さ、角丸、影、基本余白のトークン。
- `src/App.css`: トークンをTailwindの意味的な色名・文字サイズへ接続し、ボタン・パネル・入力欄などの共通スタイルを定義。
- `src/components/Icon.tsx`: 外部依存のない、装飾用の共通SVGアイコン。

別テーマは同じ`--ui-*`トークンの上書きで追加できる構成です。色の数値は各画面に直接書きません。
設定の「表示テーマ」で「ライト／ダーク／OSに合わせる」を選び、「設定を保存」で反映します。
選択だけでは切り替えず、保存失敗時は元の表示を維持します。ネイティブウィンドウにも保存済みの選択を適用します。
「OSに合わせる」は実行中のOSテーマ変更にも追従します。初回はOS追従、旧設定でテーマ未指定の場合はライトです。
CSSは`data-theme`でトークンを切り替え、OS追従は`prefers-color-scheme`の変更を監視します。
アプリ内の設定は共有し、保存直後に一覧・詳細・設定へ反映します。ウィンドウへの反映失敗は画面に表示し、再適用できます。
システムフォントを利用し、外部フォントや新しいライブラリの追加はありません。

## 一覧の表示設定

- 検索欄の近くでカード／リストを切り替えます。どの表示でもプロジェクト名を押すと詳細を開けます。
- カード表示では小・標準・大を選択できます。文字サイズは共通で、情報量・余白・カード幅を変えます。
  小はアイコン・名前・最終再開日時・再開操作のみ、標準はパス・Git状態・メモ1行も表示します。
  大は余白を広げ、前回と次の作業メモを複数行表示します。列数はウィンドウ幅から自動調整します。
- 標準のメモは「次にやること」を優先し、空なら前回の作業を表示します。全文は詳細で確認できます。
- リストは各プロジェクトを1行にまとめ、名前・パス・Git状態・最終再開日時・再開操作を表示します。
  起動結果がある場合は、その行の下に表示します。長い名前やパスは省略し、ホバーで全文を確認できます。
- 初期値はカード・標準です。変更は`settings.json`の`projectView`に自動保存し、検索・再読み込み・再起動後も維持します。
  リスト表示中はサイズ選択を隠し、カードへ戻ると前回のサイズを復元します。
- Tabで各ボタンへ移動し、Enter／Spaceで切り替えます。選択状態は見た目と`aria-pressed`の両方で示します。
- 保存中は切り替えを無効にします。保存失敗時は元の表示と入力済みデータを維持し、再試行できます。

## 一覧の並べ替え

- 表示形式の隣の「並び順」で、最近再開した順（初期値）・名前順・登録が新しい順・手動を選びます。
- すべての並び順でピン留めしたプロジェクトを先に表示します。最近再開した順では各グループで未再開のプロジェクトを末尾に置き、同日時は登録順を維持します。
  名前順は日本語と数字を自然に比較し、同名相当の場合も登録順を維持します。
  登録が新しい順は、保存データの登録順を逆にした順序です。名前やメモの編集では変わりません。
- 検索は名前・フォルダパスで絞り込み、選択中の並び順を適用します。名前の一致度による順位付けは行いません。
- 手動のときだけ移動ハンドルを表示します。ドラッグ先の枠線を確認してドロップすると、その位置へ移動します。
  ピン留めの有無が同じ項目の間で移動できます。ハンドルにTabで移動し、矢印キーで前後、Home／Endでグループの先頭／末尾にも移動できます。結果は読み上げます。
  検索中は保存済みの配置で絞り込み、移動を無効にします。
- 並び順と手動配置は`settings.json`の`projectOrder`に自動保存します。カード・リスト・サイズの変更や再起動でも維持します。
  他の並び順に切り替えても手動配置は保持し、新規登録は手動配置の先頭へ追加します。
  手動配置にないプロジェクトは新しい登録順に先頭へ補い、重複IDや登録解除済みIDは一覧から除きます。
- 保存失敗時は元の選択・配置を維持し、エラーから再試行できます。再試行は最新設定を読み、変更対象だけを保存します。

## 検証・ビルド

```sh
npm run typecheck
npm test
npm run build
cargo fmt --manifest-path src-tauri/Cargo.toml -- --check
cargo test --manifest-path src-tauri/Cargo.toml
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
npm run tauri build -- --debug --no-bundle
```

最後のコマンドでインストーラーを作成せずデスクトップ実行ファイルをビルドできます。
配布用のビルドは`npm run tauri build`です。署名・公証・配布の設定は今後対応します。

自動テストは保存・Git・起動結果・画面操作を検証しますが、ネイティブのフォルダ選択や実アプリへの起動要求は置き換えています。
macOS上での確認項目と検証範囲は[手動確認手順](macos-verification.md)を参照してください。

## ディレクトリ構成

- `src/`: React UIとスタイル
- `src/components/`: アプリ共通のレイアウト
- `src/pages/`: 画面ごとのUI
- `src/hooks/`: 一覧の読み込み状態と再試行
- `src/services/`: 型付きのRustコマンド呼び出し
- `src/types/`: UIで使用するプロジェクト型
- `src-tauri/src/lib.rs`: Rustのアプリ起動とコマンド登録
- `src-tauri/src/commands.rs`: UIと保存処理を接続するコマンドとフォルダ選択
- `src-tauri/src/projects.rs`: 入力検証とJSONの読み書き
- `src-tauri/src/projects/tests.rs`: 保存処理のテスト
- `src-tauri/src/git_status.rs`: 読み取り専用のGit状態取得
- `src-tauri/src/git_status/tests.rs`: 一時リポジトリでの状態取得と読み取り前後の比較テスト
- `src-tauri/src/launch.rs`: URL検証・起動結果の集約・OSごとのエディタ起動処理
- `src-tauri/src/launch/tests.rs`: 実アプリを起動しない起動処理のテスト
- `src-tauri/src/shortcuts.rs`: キーの検証、macOSへの登録・解除・復元
- `src-tauri/src/quick_resume.rs`: クイック再開ウィンドウと再開処理
- `src-tauri/src/settings.rs`: アプリ設定の初期値・検証・JSON保存
- `src-tauri/src/storage.rs`: 保存処理で共有するファイルロック・JSONの安全な置換
- `src-tauri/tauri.conf.json`: アプリ、ウィンドウ、CSP、ビルド設定
- `src-tauri/capabilities/`: ウィンドウに許可するTauriの権限
- `src-tauri/icons/`: アプリのビルドで使用するアイコン

OS操作と保存処理をRust側に分離しています。SQLiteへ移行する場合は、主に`ProjectStore`の読み書き部分を変更します。

## プロジェクトの登録と保存

1. デスクトップ版で「プロジェクトを追加」を押します。
2. ローカルプロジェクトでは「フォルダを選択」で選ぶか、フォルダの絶対パスを入力します。URLのみの場合は空欄にします。
3. 表示名（1〜100文字）を入力します。
4. 必要なら「起動URL（任意）」にHTTP/HTTPSのURLを入力します。フォルダなしの場合はURLが必須です。
5. 必要なら「アイコン・再開ショートカット（任意）」を開いて設定し、「登録する」を押します。

名前の前後の空白は除去します。フォルダの実在をRustで確認し、シンボリックリンクなどを解決したパスを保存します。
同じパスは重複登録できません。登録先のフォルダ内は変更しません。
起動URLはプロジェクト情報と一緒に検証・保存します。不正なURLの場合は登録せず、入力を保持してエラーを表示します。
URLは登録後も詳細画面の「起動設定」から変更・解除できます。登録しただけではエディタやブラウザは開きません。

名前は必須で、フォルダかURLの少なくとも一方が必要です。URLのみでも一覧・検索・メモ・名前の編集・登録解除を使えます。
再開時はブラウザだけを開き、Git取得やエディタ起動・エディタ設定の読み込みは行いません。
URLのみの登録は`path: null`として保存します。従来の文字列パスを持つデータもそのまま読み込みます。
複数のURLのみのプロジェクトを登録できます。同一パスの重複禁止はフォルダ付きのプロジェクトに適用します。
詳細の「プロジェクト情報を編集」でフォルダを追加・解除できます。ただしURLがない状態でフォルダは解除できず、
フォルダがない状態でURLも解除できません。先にもう一方を設定してください。

保存先はTauriの`app_data_dir()`で取得します。macOSでは通常、次の場所です。

```text
~/Library/Application Support/dev.sakuhira.desktop/projects.json
```

保存形式は`{ "version": 1, "projects": [{ "id": "UUID", "name": "表示名", "path": "絶対パス", "launchUrl": null }] }`です。
旧データの`launchUrl`省略は未設定として読み込み、読み込みだけでは書き換えません。
プロジェクトごとの`notes`には`lastWork`・`nextTask`と、`updatedAt`（UNIX時刻のミリ秒、未保存時は`null`）を保存します。
旧データの`notes`省略は空メモとして読み込みます。
`icon`は自動時に省略し、カスタム時は例として`{ "mode": "custom", "shape": "code", "color": "blue" }`を保存します。`shortcut`は未設定時に省略し、割り当てがある場合は例として`Control+KeyJ`を保存します。旧データで両項目が省略されていれば自動アイコン・ショートカット未設定として扱います。
隣接する`projects.lock`で読み取り・更新を直列化し、同時登録によるデータの取りこぼしを防ぎます。
プロジェクトが要求するRustの最小バージョンは1.90です。

ファイルが存在しない初回だけ空一覧として扱います。JSONが壊れている・未対応の形式・アクセス不可の場合は、
エラーを表示して変更を止め、既存データを上書きしません。原因を解消して「再読み込み」を押してください。
登録後にフォルダを移動・削除した場合も保存済み一覧は読み込めます。

## プロジェクトの詳細・編集・登録解除

- 一覧の「詳細を開く」で名前とフォルダを確認できます。サイドバーまたは「プロジェクト一覧に戻る」で一覧に戻ります。
- 「プロジェクト情報を編集」で名前・フォルダ・アイコン・再開ショートカットを変更し、「変更を保存」でJSONに反映します。IDと一覧の順序は保持します。
- フォルダが見つからなくなっても、パスを変えなければ名前を変更できます。新しいパスには実在するフォルダが必要です。
- 「登録を解除」は確認画面を表示し、「登録解除を確定」でsakuhiraの保存情報だけを削除します。元のフォルダとファイルは削除しません。
- 保存・登録解除に失敗した場合は画面にエラーを表示し、入力や登録情報を残します。
- 編集開始時の情報と保存済み情報を比較し、別の操作で更新・解除されたプロジェクトの上書き・削除を防ぎます。
  競合が表示されたら一覧に戻って「再読み込み」を押し、最新情報を確認してください。

## Git情報

- 一覧と詳細を開いた時、および「Gitを更新」を押した時に取得します。常時監視は行いません。
- Gitブランチ名、未コミット変更の有無、変更ファイル数を表示します。
- ステージ済み・未ステージ・未追跡の変更を含み、同じファイルは1件として数えます。
  未追跡ディレクトリ内もファイル単位で数え、Gitの無視対象は除外します。検出されたリネームは1件です。
- 登録したフォルダがリポジトリ内のサブフォルダなら、そのリポジトリ全体の状態を表示します。
  画面の「対象リポジトリ」で取得範囲を確認できます。linked worktreeにも対応しています。
- 初回コミット前はその旨を表示し、detached HEADはコミットIDの先頭7文字を表示します。
- Git管理外は通常の案内として表示します。フォルダがない・管理情報が壊れている・読み込めない場合はエラーを表示します。
  bareリポジトリは未対応のエラーとして表示します。
- Git情報はJSONに保存せず都度取得します。Git取得処理はブランチ・作業ファイル・インデックスを変更しません。
  自動切り替え、変更の破棄、Gitコマンドの実行、ネットワーク接続は行いません。

Gitのテストは一時リポジトリだけで履歴や変更を準備し、実プロジェクトの履歴には触れません。
取得前後のファイル内容を比較し、インデックス・HEAD・作業ファイルが変わらないことも確認します。

## 開発環境の再開

1. プロジェクト詳細の「起動設定」でURLを入力し、保存します（任意、1件まで）。
2. 一覧または詳細の「再開」を押します。未保存の入力ではなく、保存済みの設定を使います。

macOSではアプリ設定で選んだVS Code（Stable版、アプリ識別子`com.microsoft.VSCode`）またはCursor（アプリ名`Cursor`）を開きます。
`code`のPATH登録は不要です。`/usr/bin/open`を固定の引数で直接呼び出し、シェルや任意の実行コマンドは受け付けません。
エディタ未インストールなどの失敗は画面に表示します。起動先は保存済みのアプリ設定をRust側で読み取って決めます。
OS依存のエディタ起動は`open_editor`に集約しており、Windows版のエディタ起動はまだ未実装です。

URLはHTTP/HTTPSのみで、localhostやポート指定も使用できます。ユーザー名・パスワード入りURL、
空白・制御文字、4096バイトを超えるURLは受け付けません（URLエンコード後の長さも確認します）。
フォルダ付きのプロジェクトでは、空欄で保存するとURL設定を解除し、再開時はエディタだけを開きます。
URLのみのプロジェクトではURLは必須で、ブラウザだけを開きます。

再開の前に登録情報が最新か、フォルダが存在するか、URLが妥当かを確認します。
事前確認で失敗した場合は何も起動しません。起動開始後はエディタとブラウザの結果を個別に表示し、
一方が失敗しても他方の起動は試みます。再試行では成功済みの対象にも再度起動要求を送ります。
「起動要求を送信しました」はOSへの引き渡し結果です。VS Codeでの読み込み完了やURL先サーバーの応答までは確認しません。

自動テストはOS起動部分を置き換え、実際のエディタやブラウザを起動しません。

## プロジェクト検索

- 一覧の「プロジェクトを検索」で、名前またはフォルダパスの部分一致で絞り込みます。
- 大文字・小文字は区別せず、検索語の前後の空白は無視します。空欄・空白だけなら全件表示します。
- 一覧では選択中の並び順で検索結果を表示します。クイック再開の検索順位は[クイック再開](#クイック再開)を参照してください。
- 検索中は一致件数と全登録件数を表示します。
- 「検索をクリア」で全件に戻ります。詳細から戻っても条件を保持しますが、設定画面への移動やアプリ再起動ではリセットします。
- 新規登録後は追加したプロジェクトが見えるように検索を解除します。検索条件は保存データを変更しません。

## 最終再開日時

- フォルダ付きではエディタへの起動要求に成功した場合、Rust側の日時を`lastResumedAt`（UNIXミリ秒）に保存します。
  ブラウザだけの成功では更新せず、エディタ成功・ブラウザ失敗の場合は更新します。
  URLのみの場合はブラウザへの起動要求に成功した場合に更新します。
- 一覧と詳細に端末のタイムゾーンで表示します。過去のデータなど、日時がない場合は「記録なし」です。
  旧データのフィールド省略は`null`として読み込み、読み込みだけでは書き換えません。
- 「最近再開した順」ではピン留めの有無ごとに日時の新しい順に並び、記録なしは各グループの末尾です。日時が同じ場合は登録順です。
- 再開日時の記録だけではメモの更新日時は変わりません。編集中のメモ・設定との保存競合も起こしません。
- 起動中にプロジェクトの設定が変わった場合や保存できなかった場合は、履歴を保存せずエラーを表示します。
  起動結果はそのまま表示し、再開日時の保存のためだけにエディタを自動で再起動しません。
- 日時は処理完了時の端末時計を使います。時計が戻った場合や古い結果の到着時も、保存済み日時を過去へ戻しません。

## 作業メモ

- 詳細の「メモを編集」で前回の作業内容・次にやることを入力し、「メモを保存」で反映します。
- 各欄10,000文字（UTF-16コード単位）まで。改行や前後の空白を含め、Markdownの原文を保存します。詳細画面と編集中のプレビューは同じ表示部品を使います。生HTMLは文字、画像は代替テキストとして表示します。
- キャンセルすると入力を破棄して保存済み内容に戻ります。自動保存は行いません。
- 空欄で保存するとメモを消去できます。初回保存と内容変更時に、Rust側で更新日時を記録します。
  内容が同じ場合の再保存では日時を維持し、名前や起動URLの編集でもメモの日時は変えません。
- 更新日時は表示する端末のタイムゾーンで表示します。カードの抜粋はMarkdownからテキストを抽出し、標準は1行、大は各欄最大2行で表示します。
- 保存失敗時は入力を保持し、再試行できます。別の操作で更新された内容への上書きは拒否します。
  競合時は入力を控えて一覧を再読み込みし、最新の保存内容を確認してください。
- フォルダを移動・削除していても、保存済みメモの閲覧・編集はできます。

## アプリ全体の設定

- サイドバーの「設定」で、デフォルトエディタをVS Code／Cursorから選び、「設定を保存」を押します。
- 次の再開からすべてのプロジェクトに適用します。選択や保存だけでエディタは起動しません。
- 未保存の選択は再開に使いません。再読み込みや画面移動で、未保存の選択は破棄します。
- 設定がない初回はVS Codeを使い、読み込むだけではJSONを作成しません。
- 設定はプロジェクト情報と別の`settings.json`に保存します。通常のmacOSの保存先は次の場所です。

```text
~/Library/Application Support/dev.sakuhira.desktop/settings.json
```

保存形式は`{ "version": 1, "settings": { "defaultEditor": "vsCode", "theme": "system", "projectView": { "layout": "cards", "cardSize": "standard" }, "projectOrder": { "sort": "recent", "manualIds": [] } } }`です。
エディタは`vsCode`・`cursor`、表示テーマは`light`・`dark`・`system`に限定します。
旧設定で`theme`が省略されている場合はライトとして読み込み、読み込みだけではファイルを変更しません。
`projectView`の省略はカード・標準として読み込みます。`layout`は`cards`・`list`、`cardSize`は`small`・`standard`・`large`に限定します。
`projectOrder`の省略は最近再開した順・手動配置なしとして読み込みます。既存ファイルを読み込みだけで書き換えません。
`sort`は`recent`・`name`・`newest`・`manual`、`manualIds`と`pinnedIds`はプロジェクトID文字列の配列です。空の`pinnedIds`と未設定の`quickResumeShortcut`は省略します。
任意のコマンド、実行ファイルのパス、追加引数は設定できません。
`settings.lock`で更新を直列化し、別の操作で更新された設定の上書きは拒否します。
破損・未対応形式・読み取り失敗の場合はエラーを返し、既存JSONを保持します。エディタ設定を必要とするフォルダ付きの再開もエラーで止まります。
保存失敗時は選択を保持するので再試行できます。競合時は「設定を再読み込み」で最新情報を確認してください。
プロジェクト詳細には読み込んだデフォルトエディタを表示し、起動結果には実際に起動要求を送ったエディタ名を表示します。

## クイック再開

- 共通キーは設定の `quickResumeShortcut` に保存します。個別キーとの競合は両方向で検証し、macOSへの登録と設定保存が成功してから旧キーを解除します。
- 検索欄が空のときは最後に再開したプロジェクトを先頭に置き、残りをピン留め優先・最近再開した順で並べます。履歴がない場合はその並びの先頭を選びます。
- 検索時は名前の完全一致、前方一致、部分一致、フォルダパスの一致の順です。同順位ではピン留めと再開日時を優先し、同日時では登録順を使います。
- 一覧と同じ再開処理を使います。起動先と履歴保存がすべて成功するとウィンドウを閉じ、失敗時は検索語と選択を保持して理由を表示します。
