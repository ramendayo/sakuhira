# macOSでの手動確認

自動テストでは、保存処理・読み取り専用のGit取得・起動結果の集約・UIとIPCの接続を確認します。
OS起動処理やフォルダ選択はテスト用の処理に置き換えているため、以下はmacOSのデスクトップ版で別途確認してください。
この手順の追加は実機での確認完了を意味しません。

## 準備

- `npm run tauri dev`で起動する。
- テスト用のGitリポジトリと、Git管理されていないフォルダを用意する。
- VS CodeまたはCursorをインストールする。URL確認には機密情報を含まないHTTPSのページを使う。
- 既存の登録がある場合、Reentryを終了してからアプリデータの`projects.json`と`settings.json`を控える。
  保存先は通常`~/Library/Application Support/dev.reentry.desktop/`。

## 確認項目

1. **登録と再起動**: フォルダ選択をキャンセルしても登録されないことを確認する。
   次にフォルダを選び、名前を入力して登録する。アプリを終了・再起動し、名前とパスが残ることを確認する。
   同じフォルダの再登録はエラーとなり、既存の登録が残ることを確認する。
2. **詳細とメモ**: 名前を編集し、改行を含む前回の作業・次の作業を保存する。
   一覧のプレビューと更新日時、再起動後の内容を確認する。編集中のキャンセルで保存済み内容が変わらないことを確認する。
3. **Git**: ブランチと変更ファイル数をGit側の状態と照合する。
   テスト用ファイルを変更して「Gitを更新」を押す。Git管理外のフォルダも正常な案内になることを確認する。
   確認前後でステージ状態やブランチが変わらないことを確認する。
4. **エディタとURL**: デフォルトエディタを保存し、詳細でHTTP/HTTPSのURLを保存する。
   一覧と詳細の「再開」で対象フォルダが選択したエディタに開き、URLがデフォルトブラウザに開くことを確認する。
   URLを空欄で保存した場合はエディタだけが開くことを確認する。
   選択したエディタが未インストールの環境では、エディタの失敗が表示され、URLの起動は試行されることを確認する。
5. **エラーと再試行**: テスト用フォルダを移動してからGit更新・再開を試す。
   エラーが表示され、登録やメモが残ることを確認する。詳細で新しいパスを保存して再試行する。
6. **ナビゲーション**: Tab・Enterで設定と一覧を往復し、見出しへフォーカスが移ることを確認する。
   「メインコンテンツへ移動」も確認する。ウィンドウ最小サイズ720×520と通常サイズで、横にはみ出さず操作できることを確認する。
7. **登録解除**: 解除を一度キャンセルした後、確定する。再起動後も登録が消え、元のフォルダとファイルが残ることを確認する。

## 最終再開日時の追加後の確認

最終再開日時の追加後は、2件以上のプロジェクトを順に再開し、一覧が最近再開した順になることを確認する。
詳細・一覧・アプリ再起動後で日時が一致し、メモの更新日時は変わらないことも確認する。
エディタの起動失敗時は日時が変わらないことを確認する。

## URLのみのプロジェクトの確認

名前とHTTP/HTTPSのURLを入力し、フォルダを空欄のまま登録する。一覧・詳細・再起動後の情報を確認する。
「再開」でブラウザだけが開き、最終再開日時が更新されること、Git更新やエディタ起動が行われないことを確認する。
メモ保存・名前変更・登録解除も確認する。詳細でフォルダを追加し、URLを解除するとエディタだけを開けることを確認する。
フォルダもURLもない状態への保存はできないことを確認する。

## 表示テーマの確認

設定でライト・ダークをそれぞれ選び、保存後に一覧・詳細・設定・ウィンドウの見た目が揃うことを確認する。
未保存の選択では切り替わらないことと、アプリ再起動後も保存した選択が残ることを確認する。
「OSに合わせる」で保存し、アプリを開いたままOSをライト・ダークに切り替え、画面とウィンドウが追従することを確認する。
手動指定中はOSを切り替えてもアプリの表示が変わらないことを確認する。

## 一覧の表示形式・カードサイズの確認

カードの小・標準・大とリストを切り替え、選択状態と情報量の違いを確認する。
同じ文字サイズで、小ほど多く並び、ウィンドウ幅に応じて列数が変わることを確認する。
長い名前・パス・ブランチ名、空のメモ、URLのみのプロジェクトでも横にはみ出さないことを確認する。
名前のクリックとキーボード操作で詳細へ移動でき、各表示の再開操作が動くことを確認する。
検索・再読み込み・アプリ再起動後も表示設定が残り、リストからカードへ戻ると選択済みサイズを復元することを確認する。

## 検証の限界

- 起動成功はOSへの要求送信までを示す。エディタ内の読み込み完了やURLの応答を保証しない。
- Windowsのエディタ起動、署名・公証、インストーラーの配布は未対応。
- 技術スタックの自動検出はMVPに含めていない。
- JSON破損・保存競合・権限エラーの保護は一時ディレクトリの自動テストで検証する。
  手動確認のために普段使う保存データを壊す必要はない。
