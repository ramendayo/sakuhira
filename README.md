# Reentry

Your development workspace, one click away.

開発プロジェクトの環境と作業状況を管理し、前回の作業を再開するためのデスクトップアプリです。
macOS向けMVPを段階的に開発しています。

## 現在の実装範囲

ローカルフォルダの選択、表示名の入力、プロジェクト登録、JSON保存、保存済み一覧の表示に対応しています。
再起動時に保存データを読み込みます。Git管理されていないフォルダも登録できます。
一覧からプロジェクト詳細を開き、名前・フォルダの編集と登録解除ができます。
一覧と詳細にGitブランチ・未コミット変更の有無・変更ファイル数を表示します。
一覧と詳細の「再開」から選択したエディタと保存済みURLを開けます。起動URLは詳細で設定できます。
詳細画面で前回の作業内容・次にやることを編集でき、一覧には保存済みメモのプレビューを表示します。
アプリ全体の設定画面で、デフォルトエディタをVS Code／Cursorから選択できます。
一覧と詳細に最終再開日時を表示し、一覧は最近再開した順に並べます。

## 技術構成

- Tauri 2 / Rust: デスクトップアプリの起動と、今後追加するOS操作
- React / TypeScript: UI（strictモード）
- Vite: 開発サーバーとフロントエンドビルド
- Tailwind CSS 4 / `@tailwindcss/vite`: スタイルとViteとの統合
- `@types/node`: Vite設定内のNode.js APIを型チェックするために使用

追加した依存関係:

- `@tauri-apps/api`: UIから登録専用のRustコマンドを呼び出すため
- `tauri-plugin-dialog`: OS標準のフォルダ選択をRust側で実行するため
- `serde` / `serde_json`: 型付きデータのJSON変換のため
- `uuid`: 名前やパスに依存しないプロジェクトIDを生成するため
- `tempfile`: 同じ保存先内で一時ファイルを作り、完成したJSONに置き換えるため（テストでも使用）
- `git2`: Git CLIやシェルに依存せず、Rustでリポジトリの状態を読み取るため（SSH・HTTPSなどのデフォルト機能は無効）
- `url`: 起動URLのスキーム・ホスト・認証情報を検証し、正規化して保存するため
- `tauri-plugin-opener`: RustからOSの既定ブラウザに検証済みURLを渡すため（フロントエンドへの汎用起動権限は追加しません）
- Vitest / Testing Library / jsdom: フォーム操作と非同期の成功・失敗を検証するため

UIには汎用のファイル操作やシェル実行の権限を渡していません。

## 開発環境（macOS）

- Node.js 22.12以上の22系 / npm（`.nvmrc`を参照）
- Rust stable / Cargo
- Xcode Command Line Tools（`xcode-select --install`）

```sh
npm ci
npm run tauri dev
```

`npm run tauri dev`はViteを起動してからデスクトップウィンドウを開きます。
初回はRustの依存関係取得・コンパイルに時間がかかります。
ブラウザでUIを起動する場合は`npm run dev`を実行し、`http://localhost:1420`を開きます。
ブラウザ単体ではRust機能を使えないため、一覧の代わりにデスクトップ版の起動案内を表示します。
終了は起動したターミナルでCtrl+Cです。

## 検証・ビルド

```sh
npm run typecheck
npm test
npm run build
cargo fmt --manifest-path src-tauri/Cargo.toml -- --check
cargo test --manifest-path src-tauri/Cargo.toml
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
npm run tauri build -- --debug --no-bundle
```

最後のコマンドでインストーラーを作成せずデスクトップ実行ファイルをビルドできます。
配布用のビルドは`npm run tauri build`です。署名・公証・配布の設定は今後対応します。

自動テストは保存・Git・起動結果・画面操作を検証しますが、ネイティブのフォルダ選択や実アプリへの起動要求は置き換えています。
macOS上での確認項目と検証範囲は[手動確認手順](docs/macos-verification.md)を参照してください。

## ディレクトリ構成

- `src/`: React UIとスタイル
- `src/components/`: アプリ共通のレイアウト
- `src/pages/`: 画面ごとのUI
- `src/hooks/`: 一覧の読み込み状態と再試行
- `src/services/`: 型付きのRustコマンド呼び出し
- `src/types/`: UIで使用するプロジェクト型
- `src-tauri/src/lib.rs`: Rustのアプリ起動とコマンド登録
- `src-tauri/src/commands.rs`: UIと保存処理を接続するコマンドとフォルダ選択
- `src-tauri/src/projects.rs`: 入力検証とJSONの読み書き
- `src-tauri/src/projects/tests.rs`: 保存処理のテスト
- `src-tauri/src/git_status.rs`: 読み取り専用のGit状態取得
- `src-tauri/src/git_status/tests.rs`: 一時リポジトリでの状態取得と読み取り前後の比較テスト
- `src-tauri/src/launch.rs`: URL検証・起動結果の集約・OSごとのエディタ起動処理
- `src-tauri/src/launch/tests.rs`: 実アプリを起動しない起動処理のテスト
- `src-tauri/src/settings.rs`: アプリ設定の初期値・検証・JSON保存
- `src-tauri/src/storage.rs`: 保存処理で共有するファイルロック・JSONの安全な置換
- `src-tauri/tauri.conf.json`: アプリ、ウィンドウ、CSP、ビルド設定
- `src-tauri/capabilities/`: ウィンドウに許可するTauriの権限
- `src-tauri/icons/`: テンプレートのアイコン（ブランド用アイコンは未作成）

OS操作と保存処理をRust側に分離しています。SQLiteへ移行する場合は、主に`ProjectStore`の読み書き部分を変更します。

## プロジェクトの登録と保存

1. デスクトップ版で「プロジェクトを追加」を押します。
2. 「フォルダを選択」で選ぶか、フォルダの絶対パスを入力します。
3. 表示名（1〜100文字）を入力し、「登録する」を押します。

名前の前後の空白は除去します。フォルダの実在をRustで確認し、シンボリックリンクなどを解決したパスを保存します。
同じパスは重複登録できません。登録先のフォルダ内は変更しません。

保存先はTauriの`app_data_dir()`で取得します。macOSでは通常、次の場所です。

```text
~/Library/Application Support/dev.reentry.desktop/projects.json
```

保存形式は`{ "version": 1, "projects": [{ "id": "UUID", "name": "表示名", "path": "絶対パス", "launchUrl": null }] }`です。
旧データの`launchUrl`省略は未設定として読み込み、読み込みだけでは書き換えません。
プロジェクトごとの`notes`には`lastWork`・`nextTask`と、`updatedAt`（UNIX時刻のミリ秒、未保存時は`null`）を保存します。
旧データの`notes`省略は空メモとして読み込みます。
隣接する`projects.lock`で読み取り・更新を直列化し、同時登録によるデータの取りこぼしを防ぎます。
ロックAPIにはRust 1.89以上を使用します（依存関係のビルドには最新stableを推奨）。

ファイルが存在しない初回だけ空一覧として扱います。JSONが壊れている・未対応の形式・アクセス不可の場合は、
エラーを表示して変更を止め、既存データを上書きしません。原因を解消して「再読み込み」を押してください。
登録後にフォルダを移動・削除した場合も保存済み一覧は読み込めます。

## プロジェクトの詳細・編集・登録解除

- 一覧の「詳細を開く」で名前とフォルダを確認できます。サイドバーまたは「プロジェクト一覧に戻る」で一覧に戻ります。
- 「編集する」で名前・フォルダを変更し、「変更を保存」でJSONに反映します。IDと一覧の順序は保持します。
- フォルダが見つからなくなっても、パスを変えなければ名前を変更できます。新しいパスには実在するフォルダが必要です。
- 「登録を解除」は確認画面を表示し、「登録解除を確定」でReentryの保存情報だけを削除します。元のフォルダとファイルは削除しません。
- 保存・登録解除に失敗した場合は画面にエラーを表示し、入力や登録情報を残します。
- 編集開始時の情報と保存済み情報を比較し、別の操作で更新・解除されたプロジェクトの上書き・削除を防ぎます。
  競合が表示されたら一覧に戻って「再読み込み」を押し、最新情報を確認してください。

## Git情報

- 一覧と詳細を開いた時、および「Gitを更新」を押した時に取得します。常時監視は行いません。
- Gitブランチ名、未コミット変更の有無、変更ファイル数を表示します。
- ステージ済み・未ステージ・未追跡の変更を含み、同じファイルは1件として数えます。
  未追跡ディレクトリ内もファイル単位で数え、Gitの無視対象は除外します。検出されたリネームは1件です。
- 登録したフォルダがリポジトリ内のサブフォルダなら、そのリポジトリ全体の状態を表示します。
  画面の「対象リポジトリ」で取得範囲を確認できます。linked worktreeにも対応しています。
- 初回コミット前はその旨を表示し、detached HEADはコミットIDの先頭7文字を表示します。
- Git管理外は通常の案内として表示します。フォルダがない・管理情報が壊れている・読み込めない場合はエラーを表示します。
  bareリポジトリは未対応のエラーとして表示します。
- Git情報はJSONに保存せず都度取得します。Git取得処理はブランチ・作業ファイル・インデックスを変更しません。
  自動切り替え、変更の破棄、Gitコマンドの実行、ネットワーク接続は行いません。

Gitのテストは一時リポジトリだけで履歴や変更を準備し、実プロジェクトの履歴には触れません。
取得前後のファイル内容を比較し、インデックス・HEAD・作業ファイルが変わらないことも確認します。

## 開発環境の再開

1. プロジェクト詳細の「起動設定」でURLを入力し、保存します（任意、1件まで）。
2. 一覧または詳細の「再開」を押します。未保存の入力ではなく、保存済みの設定を使います。

macOSではアプリ設定で選んだVS Code（Stable版、アプリ識別子`com.microsoft.VSCode`）またはCursor（アプリ名`Cursor`）を開きます。
`code`のPATH登録は不要です。`/usr/bin/open`を固定の引数で直接呼び出し、シェルや任意の実行コマンドは受け付けません。
エディタ未インストールなどの失敗は画面に表示します。起動先は保存済みのアプリ設定をRust側で読み取って決めます。
OS依存のエディタ起動は`open_editor`に集約しており、Windows版のエディタ起動はまだ未実装です。

URLはHTTP/HTTPSのみで、localhostやポート指定も使用できます。ユーザー名・パスワード入りURL、
空白・制御文字、4096バイトを超えるURLは受け付けません（URLエンコード後の長さも確認します）。
空欄で保存するとURL設定を解除し、再開時はエディタだけを開きます。

再開の前に登録情報が最新か、フォルダが存在するか、URLが妥当かを確認します。
事前確認で失敗した場合は何も起動しません。起動開始後はエディタとブラウザの結果を個別に表示し、
一方が失敗しても他方の起動は試みます。再試行では成功済みの対象にも再度起動要求を送ります。
「起動要求を送信しました」はOSへの引き渡し結果です。VS Codeでの読み込み完了やURL先サーバーの応答までは確認しません。

自動テストはOS起動部分を置き換え、実際のエディタやブラウザを起動しません。

## 最終再開日時

- エディタへの起動要求に成功した場合、Rust側の日時を`lastResumedAt`（UNIXミリ秒）に保存します。
  ブラウザだけの成功では更新せず、エディタ成功・ブラウザ失敗の場合は更新します。
- 一覧と詳細に端末のタイムゾーンで表示します。過去のデータなど、日時がない場合は「記録なし」です。
  旧データのフィールド省略は`null`として読み込み、読み込みだけでは書き換えません。
- 一覧は日時の新しい順、記録なしは後ろです。同じ日時や記録なし同士では元の登録順を維持します。
- 再開日時の記録だけではメモの更新日時は変わりません。編集中のメモ・設定との保存競合も起こしません。
- 起動中にプロジェクトの設定が変わった場合や保存できなかった場合は、履歴を保存せずエラーを表示します。
  起動結果はそのまま表示し、再開日時の保存のためだけにエディタを自動で再起動しません。
- 日時は処理完了時の端末時計を使います。時計が戻った場合や古い結果の到着時も、保存済み日時を過去へ戻しません。

## 作業メモ

- 詳細の「メモを編集」で前回の作業内容・次にやることを入力し、「メモを保存」で反映します。
- 各欄10,000文字まで。改行や前後の空白はそのまま保存し、HTMLとしては解釈しません。
- キャンセルすると入力を破棄して保存済み内容に戻ります。自動保存は行いません。
- 空欄で保存するとメモを消去できます。初回保存と内容変更時に、Rust側で更新日時を記録します。
  内容が同じ場合の再保存では日時を維持し、名前や起動URLの編集でもメモの日時は変えません。
- 更新日時は表示する端末のタイムゾーンで表示します。一覧のプレビューは各欄2行までです。
- 保存失敗時は入力を保持し、再試行できます。別の操作で更新された内容への上書きは拒否します。
  競合時は入力を控えて一覧を再読み込みし、最新の保存内容を確認してください。
- フォルダを移動・削除していても、保存済みメモの閲覧・編集はできます。

## アプリ全体の設定

- サイドバーの「設定」で、デフォルトエディタをVS Code／Cursorから選び、「設定を保存」を押します。
- 次の再開からすべてのプロジェクトに適用します。選択や保存だけでエディタは起動しません。
- 未保存の選択は再開に使いません。再読み込みや画面移動で、未保存の選択は破棄します。
- 設定がない初回はVS Codeを使い、読み込むだけではJSONを作成しません。
- 設定はプロジェクト情報と別の`settings.json`に保存します。通常のmacOSの保存先は次の場所です。

```text
~/Library/Application Support/dev.reentry.desktop/settings.json
```

保存形式は`{ "version": 1, "settings": { "defaultEditor": "vsCode" } }`です。選択肢は`vsCode`・`cursor`に限定します。
任意のコマンド、実行ファイルのパス、追加引数は設定できません。
`settings.lock`で更新を直列化し、別の操作で更新された設定の上書きは拒否します。
破損・未対応形式・読み取り失敗の場合は初期値へ戻さず、再開もエラーで止めます。既存JSONを上書きしません。
保存失敗時は選択を保持するので再試行できます。競合時は「設定を再読み込み」で最新情報を確認してください。
プロジェクト詳細には読み込んだデフォルトエディタを表示し、起動結果には実際に起動要求を送ったエディタ名を表示します。
